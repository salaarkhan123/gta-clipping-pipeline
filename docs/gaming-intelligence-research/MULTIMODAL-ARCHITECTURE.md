# Multimodal selection for recorded gaming streams

A useful clip has an identifiable payoff and enough setup to understand it. A detector that reliably finds a goal can still fill a list with routine goals. Conversely, a player can quietly talk their way out of trouble while the game state barely changes. Model **event occurrence**, **editor preference** and **public audience response** as separate targets. Only the first two belong in the initial discovery experiment. [Gaming highlights using game, speech and face views](https://arxiv.org/abs/1807.09715) · [Study of audience response](VIRALITY-RESEARCH.md)

## Interfaces and time alignment

Use source presentation timestamps (PTS), in seconds from the start of the original recording. If the observation is extracted from a job range, restore its absolute offset once. Keep the uncertainty of sparse sampling and ASR timing. A detector can localize the final banner well after the action that caused it. Keep observation time, estimated event interval and proposed clip boundaries independently.

| Record | Required fields | Example use |
|---|---|---|
| Observation | Source/range ID, stream clock, start/end, observed-at PTS, modality, class, raw score, profile and extractor version, ROI/actor role, available flag, missing reason | A score rises after a shot. OCR read two changed digits. Camera reaction starts later. Each observation has evidence that an editor can inspect privately. |
| Event | Source-unique episode ID, game/mode, class, actor/target if known, before/after state, supporting and contradictory observation IDs, calibrated class confidence, confidence interval for event time | Round win for the observed team, scorer unknown. A replay refers to the same episode if supported by clock and score. |
| Candidate | Source intervals, event IDs, setup/peak/payoff/tail, available channels, context before/after, nomination route, score components, estimator hash, original selector rank | Allows fixed-pool ranking tests and full-discovery tests to use the same labels and timing. |
| Run | Source and split manifest hashes, product SHA, detector and weight hashes, decoder/PTS policy, threshold set, ASR/judge configuration and response cache, limits, compute/cost counters | Replays are attributable even after a patch, model update, or VOD re-encode. |

Persist experimental records in a private sidecar. Public PRs can contain fixtures with invented identifiers and aggregate metrics. Feature caches expire with source deletion and rights withdrawal. Store anonymized chat counts or observable face motion where permitted. There is no need to identify a face, keep voiceprints or infer a person's emotional state.

## Candidate generation and ranking

1. **Route segments.** Start with creator-provided game/mode and template hints. Verify against title-specific anchors with change hysteresis. On disagreement mark the segment unknown, continue generic scoring and avoid game-specific decode. Break at game changes, replays, scene cuts, clock resets or a shift to intermission. Measure game recognition per segment, transition delay, and unknown rejection on unseen creators. [Game-specific detectors](GAME-SPECIFIC-DETECTORS.md)
2. **Generate a broad, cheap pool.** Keep baseline candidates and transcript proposals. Add independently nominated high-confidence game events, quiet story/turn-taking candidates and a fixed uniform coverage sample in shadow runs. Merge intervals sharing an event ID. Give each route a preregistered quota so bursts of gunfire cannot crowd out dialogue. A separate uniform audit over excluded seconds measures candidate-generation misses.
3. **Assemble evidence around an event.** Sample the raw HUD only inside known regions, using consecutive crop changes to mark onset, persistence and reset. Read peaks and onsets from reused PCM. Use transcript speaker turns only when available. Compare mouth/head motion with the same facecam's local baseline. Estimate chat response lag on development events, retain uncertainty, and fall back to a missing indicator on low-volume or absent chat. Do not align by maximizing test-set agreement. [Chat-based detection and boundary study](https://dbgroup.cs.tsinghua.edu.cn/jnwang/papers/lightor.pdf)
4. **Separate event confidence from entertainment.** First fit per-class calibration on independently annotated development seconds/episodes. Then fit a small regularized logistic or ordinal ranker on editor labels. Inputs include class confidence, rarity normalized within game/mode, leverage (score/time/alive state), reaction delay, transcript payoff, intro/exit completeness, playable POV, scene state and missingness. Restrict interactions to interpretable pairs such as confirmed event × stakes and semantic payoff × delayed response. Compare against a simple fixed late fusion at the same candidate and compute budget. For sparse games, pool effects by genre and shrink game-specific effects toward the shared model.
5. **Reduce repeated and spurious nominations.** Correlated loudness, flux and predicted gunshot are one audio family. Aggregate them before fusion or cap that family's contribution. Tag alerts, replay, spectator switching, menus/BRB and ads as competing explanations. Apply penalties only in the experimental arm. Keep the first live event with context and optionally its reaction. An official replay can be the only view of the action, so annotate it as an alternate representation. Compare the current dHash/variety pass with episode-based suppression at equal K.
6. **Choose the cut and rank.** Starting from a peak, search backwards for intelligible setup or state change and forwards for outcome/reaction within the requested bucket. Use sentence endings and cuts already available in #218. Assign repeated views zero additional gain. Optionally run a bounded VLM only on ambiguous shortlisted intervals, with timestamped frames, transcript and an explicit “insufficient evidence” output. Accept a claimed event only if its cited frame/time exists. Cache by model, frames and prompt. On timeout use the preceding score. ## Three examples for reviewers

| Sequence | What raises relevance | Counterexample that should lose |
|---|---|---|
| Valorant active POV, teammate eliminated, two opponent eliminations, round ends, then celebration | Perspective and changing team score corroborate the round. The candidate begins before the first decisive play and includes the result. | A kill feed streams past while spectating another teammate. Music and overlay alerts spike. The winner and POV are uncertain. |
| Quiet GTA RP negotiation, callback to an earlier line, reversal, pause then laughter | Transcript and turn boundaries supply setup and payoff. Delayed audience response can corroborate the reversal. Game HUD may be absent throughout. | A loud police siren continues for minutes while two players exchange routine directions. |
| Rocket League shows a goal, the score increments once, crowd cheers, replay repeats the finish | A transition into overtime or a lead change increases stakes. The state machine groups the replay and the live goal. | An overlay displays an earlier highlight during a tied game, with no local score transition. |

## Calibration, fallback and promotion

Split development by creator and source before fitting, with a separate calibration partition. Compare logistic/temperature scaling with isotonic only when support is sufficient. Report Brier score, equal-frequency reliability bins with counts, coverage versus error by confidence, and per-class precision/recall. Estimate calibration of “editor would publish” separately from “event occurred.” Do not expose either as a forecast of views. Version thresholds by model, class and supported layout, defaulting to abstention outside support. [Calibration study](https://proceedings.mlr.press/v70/guo17a.html)

The clean control runs the existing selector with no experimental input. Ordinary jobs must skip model loading, decode, sidecar writes, prompt changes and vetoes when disabled. An explicitly enabled research runner may compute observations with production ranking weight zero. It writes only to the research sidecar. Verify byte-identical serialized candidate content/order using fixed judge responses and stable timestamps. Failures in an experimental arm retain the baseline output and count toward runtime and availability. Promote one class or interaction at a time only against the preregistered quality, timing and cost gates. [Phased roadmap](IMPLEMENTATION-ROADMAP.md)
