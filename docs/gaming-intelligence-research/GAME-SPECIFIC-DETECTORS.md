# Game-specific detectors

Use one timestamped signal interface, per-title configuration for stable HUDs and a learned detector only where the inexpensive methods miss valuable events. These are proposed VOD experiments. The linked publisher material documents underlying game mechanics or UI features. Its examples do not establish that a given stream exposes the feature, in a particular location, on the current patch.

## Routing a VOD

1. Record any explicit creator selection, reliable time-bounded stream category and its provenance. Treat a category as a prior. Just Chatting before a match, desktop switches, react content and tournament intermissions can all retain the old category.
2. Find the active picture and normalized coordinate transform once per stable layout. Infer mode (player POV, broadcast, spectate, menu, replay) separately from title. A letterboxed 1080p source and a vertical recording of it need different regions of interest. Unsupported layouts produce missing fields.
3. Where category and visual anchors agree, route directly. For conflicts or missing metadata, trial a frozen DINOv2 ViT-S/14 probe on sparse frames, e.g. every 20 s and after sustained scene changes. Train the probe on licensed development-only frames with disjoint creators, games and overlays in the unknown test. Require a calibrated top-two margin and repeated agreement across samples. Include unrelated titles, animation, real-world sports, ads and webcam-only frames in the unknown class. [DINOv2](https://github.com/facebookresearch/dinov2)
4. Keep title confidence, HUD/layout version, mode and missingness in each record. Reset state on a stable game switch, match reset or replay entry. Do not allow a low-confidence router or unreadable frame to remove candidates from the universal audio/transcript/chat path.

## OCR and event validation

Give each field an expected vocabulary or type, patch/layout identifier and state transition grammar. For the initial Rocket League score experiment, annotate the tuple (left score, right score, clock, state) and whether each field is readable. Preserve original timecodes. Generate identical crops for all readers, including negatives from timers, replay wipes, menus and partial occlusion. Compare a masked pixel/template baseline, Tesseract integer English weights and PaddleOCR mobile recognition. Upscale from native pixels and preserve aspect ratio. A numeric whitelist belongs on scores, never on player names. [OCR candidates](REPOSITORY-EVALUATION.md)

Try 1–2 Hz sparse score sampling and short 4–8 Hz bursts around change or ambiguous evidence. These are starting settings. For subsecond feed rows, include a dense reference pass on short held-out sequences to quantify misses from the sparse schedule. Compare single-read acceptance with two-of-three persistence. Timestamp an event at its first corroborated read, report any resulting delay and detect new rows by insertion across adjacent frames. When a wipe clears and the same score returns, keep the previous event identity. An impossible score jump is missing evidence until confirmed.

Report exact-field and complete-tuple accuracy on readable examples, accepted precision, readable-field coverage, false accepted events per gameplay hour, median/p95 onset error and end-to-end incremental compute. Break out patch, creator, language, 480p/720p/1080p, native/letterboxed/vertical, POV, hidden HUD and replay. Include frames with zero events in the denominator for false-event rates. A proposed initial target is at least 95% accepted event precision with at least 80% readable-event coverage on supported layouts, plus a reported creator-grouped confidence interval. Thresholds belong on development footage. Promotion still depends on a demonstrated improvement in the full ranker with the agreed budget. [Evaluation framework](EVALUATION-FRAMEWORK.md)

Start with Rocket League score changes because a score delta has a cheap, falsifiable reference and replay errors are observable. In parallel, evaluate GTA RP narrative moments on the existing title focus. Add a shooter pilot using Valorant personal-versus-assist attribution once labeled footage is available. Other titles enter one at a time with supported layouts, negative cases and title-specific evidence, while the universal path covers every upload. [Roadmap](IMPLEMENTATION-ROADMAP.md)
