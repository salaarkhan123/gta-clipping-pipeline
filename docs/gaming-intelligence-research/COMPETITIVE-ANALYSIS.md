# Gaming clipping competitors

Wayin already advertises GTA V templates and reaction-aware clipping. OpusClip already supports footage with little dialogue. Game awareness or multimodal input alone would therefore be weak differentiation. The question for ClutchClips is whether it returns more clips an editor would actually publish from the same stream, with less searching and trimming. ## Where an advantage could be demonstrated

One historical comparison is reproducible without a vendor upload. ClutchClips' saved reaction-VOD run overlaps 7 of 15 Wayin picks. PR #154 reported 10 of those 15 after testing audio-feature weights on the same recording. The 15 picks were all assigned a positive rating by convention. This measures overlap with a vendor's selections and says little about head-to-head gaming preference. [Original scorer and study protocol](https://github.com/salaarkhan123/gta-clipping-pipeline/blob/3d684f8e03b02257467e03fb9dc4fcb297499e13/clip-api/eval/README.md) · [Historical audio comparison](https://github.com/salaarkhan123/gta-clipping-pipeline/pull/154)

| Hypothesis | Hard comparison |
| --- | --- |
| A player-specific round transition identifies high-stakes clutches more precisely. | Pair first-person clutches with spectator, killcam, replay and ordinary trade-kill negatives. Count duplicate clips and mistaken attribution. Compare against a timestamp-only game event baseline when paired telemetry is available. |
| Dialogue setup and delayed reactions recover quiet GTA RP stories. | Mix quiet punchlines, empty car rides, loud non-events and similar dialogue without a payoff. Include VODs with chat unavailable. Ask editors whether a newcomer can understand the payoff and measure seconds of boundary repair. |
| Uncertainty estimates help editors screen clips faster. | Mix intact and obscured HUDs, new patches and streamers with custom overlays. In a separate usability arm, randomize evidence display and measure minutes to select five publishable clips. A higher model confidence has to track measured reliability. |

These are hypotheses about ClutchClips. A vendor’s public silence about a detector, or an example chosen for a marketing page, says little about how often that product would fail on these tests.

## Paired benchmark for a later approved run

1. Freeze the inputs before opening a vendor account. Use new creator-consented VODs with explicit permission to upload to every included service. Hash the media and document title, patch, language, POV, overlay, resolution, audio mix and chat availability. Block by creator and game, with silent, low-motion and no-highlight sessions. Human editors independently annotate complete timelines and adjudicate disagreements before seeing system outputs.
2. Run two modes separately. For automatic discovery, use default gaming mode, the same full timeframe, the same clip-length range where supported, and no prompt or edits. For prompted retrieval, preregister the same short event query per title and record unsupported settings. Keep submission order randomized across tools/time slots. Record plan, date, region, configuration, returned count, ordering and failures. Repeat selected identical inputs to estimate variability.
3. Preserve each tool’s first five results as returned. If fewer are available, report yield and count missing ranks as zero gain. Project candidate intervals back to original source time. For stitched clips, retain ordered source segments and mark noncontiguous edits. Count each gold event once. Record generation mode, native score and ordinal rank. Compare ranks within each tool.
4. Blind and randomize two review panels. One rates uniformly rendered source intervals for event relevance, setup/payoff and boundary quality. The other rates native exports for captions, facecam crop and publishability. Mask identifying branding where permitted and record residual unblinding. Measure editor repair time separately. This separates highlight discovery from editing work.
5. Measure upload completion, first playable preview and last requested export ready from a common submission clock. Include failed or timed-out jobs, exact wall times, retries, credits, actual charged USD and input hours. For Outplayed, capture a supported match live on a consenting client alongside the video. Report its event recall on those matches as a separate stratum.
6. Report paired creator/VOD-clustered intervals for NDCG@5, precision@5, event recall, human preferences including ties, boundary error, review minutes, and cost per input hour. Disclose unsupported games and missing exports. Set a noninferiority margin, primary quality outcome, cost ceiling and replication cohort before opening results. Claim parity or superiority only for the tested modes and titles whose uncertainty intervals clear those gates. Use the matching and uncertainty rules in the [evaluation framework](EVALUATION-FRAMEWORK.md).
