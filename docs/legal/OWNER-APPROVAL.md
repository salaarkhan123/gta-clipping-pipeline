# Legal content that needs the owner

Status at release candidate 23b079b plus the `release/legal-trust-finish` branch. The six legal routes are stubs in a production build, and the drafts are not published. Nothing here is legal advice. The drafts were written by software from the code and from your 2026-11-18 decisions, and they have not been reviewed by a lawyer. Counsel review is recommended for every row marked "legal review".

## How the pages are controlled

- A normal build (`npm run build`) shows each of `/terms/ /privacy/ /copyright/ /refunds/ /cookies/ /acceptable-use/` as a title plus "This policy is being finalised. Contact <address>." (terms, refunds and acceptable-use: support@; privacy and cookies: privacy@; copyright: copyright@ and a link to the report form `/takedown/`).
- `scripts/check-legal.mjs` fails the build if any page still contains an `[OWNER ...]` marker. The default is the safe state.
- The drafts exist in `clip-api/web-src/app/<page>/page.tsx` and render only when built with `LEGAL_PREVIEW=1`. Never copy a preview build into `clip-api/web`.
- To publish after approval: (1) replace each `OWNER.*` value in `web-src/lib/legal.ts` with the real fact and delete its `<Owner>` marker in the page, resolve each `<Decision>`, remove `<Review />` and `<Outstanding>` marks once counsel has cleared them; (2) delete the stub branch in `components/LegalPage.tsx` (`if (!PREVIEW) return <Stub .../>`); (3) change the version from `1.0-draft` to the approved one in both `app/legal.py` and `web-src/lib/legal.ts` (the test `test_site_lists_the_same_policies_as_the_api` keeps them equal), which makes every account re-accept (`consent_required`); (4) set `REQUIRE_TERMS_ACCEPTANCE=true` in the API environment; (5) rebuild with `npm run build`.
